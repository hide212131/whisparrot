## 1. 設計方針と決定の境界

第1段の認識に **ローカル / クラウドの排他的な選択**を追加し、既定をローカルとする。クラウドは利用者が指定した OpenAI 互換の音声文字起こし API へ、録音停止後に一回のファイル要求を送る。認識が成功した後は、既存の第2段（互換エンドポイント / ChatGPT / OFF）と投入へ合流する。

想定構成は `whisparrot → LiteLLM プロキシ → Azure OpenAI の文字起こしモデル`。アプリが知るのは互換 API の URL、Bearer キー、モデル名だけである。Azure のデプロイ URL、`api-key` ヘッダー、`api-version`、資格情報、プロバイダー切替をアプリの設定・要求へ追加しない。これらの変換と、バックエンドのフォールバック・負荷分散は LiteLLM 側の責務とする。

LiteLLM の公式資料には、`/v1/audio/transcriptions` への multipart の `file` / `model` と Bearer 認証、openai / azure の対応、フォールバック・負荷分散が掲載されている。アプリはこの共通契約だけを採用する。[LiteLLM 文字起こし API](https://docs.litellm.ai/docs/audio_transcription)（2026-11-18 確認）

| 案 | 利点 / 負担 | 判断 |
| --- | --- | --- |
| ローカル / クラウド排他 | 音声の送信条件と失敗の原因が明確。ローカルモデルなしでもクラウドを使える | **推奨**。同一発話に認識要求は一つ |
| 並列認識して結果を選ぶ | 速度・精度の比較はできるが、二重処理、結果選択、取消、音声送信条件が増える | 採らない |
| クラウド優先＋ローカル自動復帰 | 接続不能時に救済できるが、モデル取得・起動・待ち時間がクラウド選択に付随する | §5 で比較。初回追加には採らない |

ローカルの Whisper ワーカー、small の既定、GPU / CPU 復帰、モデル取得は既存契約を維持する。ChatGPT の接続は T13 で実装済みとして扱い、前任設計の D-1 を再検討しない。整文失敗時の原文投入、15 秒期限、投入失敗時の一件保持も本追加で変更しない。

## 2. 確認した現行実装と変更点

| 現行の単位 | 確認した事実 | 追加する責務 |
| --- | --- | --- |
| `Core/Abstractions.cs` | `PcmAudio(float[] Samples)` は 16,000 Hz mono。`IRecognizer` は `CheckReady()` と `RecognizeAsync(RecognitionRequest, ct)`、結果は Text / Backend | 認識契約の説明をエンジン共通にする。Core に HTTP / WAV / DPAPI を持たせない |
| `Infrastructure/Audio/WasapiRecorder.cs` | WASAPI の形式から float mono へ変換して蓄積し、停止時に 16 kHz へリサンプル。停止要求後 250 ms の末尾回収を行う | 録音・リサンプルは共通利用。クラウド側でだけ PCM16 WAV を生成 |
| `Infrastructure/Recognition/WhisperRecognizer.cs` | 子プロセス・IPC、モデルの準備確認と認識、取消時の子終了、実行方式の報告 | ローカル実装を継続利用。クラウド HTTP をワーカーへ載せない |
| `Core/SessionCoordinator.cs` | イベントを直列化し、認識準備確認後に録音開始。整文の構えは録音開始時固定。取消で session ID を進め、遅延完了を破棄 | クラウドの構えも開始前に固定。成功以降は同じ経路、認識失敗は非投入で Idle |
| `Infrastructure/Network/NetworkContext.cs` | 実際の enum 名は `NetworkPurpose`。Cleanup だけに loopback HTTP を許可し、Cleanup 以外には GET/HEAD 転送用 policy を設定 | Transcription を追加。HTTP 例外・転送禁止・期限を明示的に分類する |
| `Infrastructure/Settings/SettingsJson.cs` | schema 1、未知キー・重複・不正型を拒否。追加例 `proxy.manual_auth` は既定時に書き出さない | 同じ規律で認識設定を拡張。旧設定の通常保存で追加キーを作らない |
| `App/TrayApp.cs` / `Views/SettingsWindow.cs` | 常駐起動時にローカルモデル状態を検査し、未取得なら設定を開く。UI にはローカル認識領域がある | 起動時のモデル案内をローカル選択時だけに限定。クラウド選択時はローカルモデルを要求しない |

前任設計は全設定のセッション固定を意図するが、現行 NetworkContext はクライアント生成時の proxy 設定を使う。本追加では既存の通信設定適用時点を維持し、クラウド URL / モデル / キー / エンジンだけを録音開始時に固定する。整文側やローカル側の設定適用挙動を変更する作業へ広げない。

## 3. 全体アーキテクチャとセッション

### 3.1 配置と依存方向

```text
Core/                         認識選択・準備結果、SessionCoordinator、音声値型
Infrastructure/Recognition/  SettingsRecognizer（選択）、CloudTranscriber（HTTP）、WAV 変換
                              WhisperRecognizer（既存の子プロセス隔離）
Infrastructure/Network/      NetworkContext / NetworkPurpose.Transcription
App/                         結線、設定 UI、ピル、診断モード
```

クラウドは **親プロセス内の非同期 HTTP** とする。ネイティブエンジンのクラッシュ隔離のためのワーカーを経由しても HTTP の利益は少なく、秘密と multipart を IPC に追加する負担が増える。UI スレッドや Coordinator のイベントループでエンコード・送受信を同期実行しない。

`SettingsRecognizer` は新しい選択用アダプターとし、開始前に `RecognitionSetup` を作る。形は `Unconfigured(固定文言の理由)` / `Ready(Engine, 認識関数, Deadline)`。Deadline はクラウドだけ 60 秒、ローカルは既存どおり追加の時間制限なしとする。これは M3 の `PolishSetup` の流儀に合わせた予定契約である。

ローカルの構えは既存 `WhisperRecognizer.CheckReady` と認識呼出しに委譲する。クラウドの構えは、設定が利用可能で URL / モデル / キーが妥当か確認して DPAPI を復号し、不変の値を捕捉する。準備でネットワーク疎通、モデル一覧、ワーカー起動、ローカルモデル取得を行わない。未準備なら録音を始めず設定へ案内する。キーはその構えの寿命に限ってメモリに保持し、失敗・取消・完了で参照を解放する。

Core はクラウドの HTTP 実装を参照しない。認識関数は既存 `RecognitionRequest(PcmAudio, "ja")` と `RecognitionResult` を利用できる。クラウド成功の Backend は固定識別子 `cloud` とし、背後で動いたモデルや GPU を推測しない。ローカルの既存 Backend はそのまま返す。

### 3.2 パイプラインと状態遷移

| 現在状態 / 条件 | 処理 | 次状態 |
| --- | --- | --- |
| Idle、ローカル選択 | 従来の準備確認、録音開始 | Recording |
| Idle、クラウド準備済み | クラウドの構えを固定、マイク開始 | Recording |
| Idle、クラウド未設定 / キー復号不能 | 固定の短い理由を通知。HTTP・録音なし、暗号文は保持 | Idle |
| Recording、停止 | 既存の末尾回収後 PCM を確定。空サンプルなら HTTP なし | Recognizing / Idle |
| Recognizing、クラウド | 上限検査、WAV 化、Transcription 経由の POST、JSON 受信 | Recognizing |
| Recognizing、非空 text 成功 | 既存の整文の構えへ渡す。OFF は直接投入 | Polishing / Inserting |
| Recognizing、空 text / 失敗 / 期限超過 | 非投入、短い理由を通知、PCM と要求資源を解放 | Idle |
| Recording / Recognizing、取消 | 録音または HTTP を取り消し、session ID を進める。整文・投入しない | Idle |
| Polishing / Inserting 以降 | 既存どおり。整文失敗はクラウドで得た原文を投入、投入失敗は一件保持 | 既存遷移 |

認識失敗には原文がないため、現行の `Failed`（未投入テキストあり）を流用しない。`RetryInsert` は音声を再送する操作にしない。処理中のホットキーで新録音を始めず、録音キューも追加しない。

クラウドの期限は HTTP と Coordinator の両方で守る。期限超過ではトークンを取り消し、要求・応答・ストリームを dispose して結果を不採用にする。取消を無視した代役が後で成功しても、同じ ID・Recognizing 中の一回だけを受理する境界で排除する。期限を迎えたセッションを終了させ、新セッションへ古い完了を渡さない。例外を未観測のまま残さない。

一つの認識を終えるまで PCM を所有し、認識後は音声を整文へ渡さない。不要な WAV 全体の多重コピーを避ける。管理メモリの参照解放は物理的な即時消去の保証ではない。取消済み HTTP の後始末にも有限時間で収束することを試験する。送信済みの音声が接続先で処理・課金されることまで取消できるとは表示しない。

### 3.3 ピルと実行方式表示

前任設計 §6.1 の幅・非アクティブ表示・停止 / 取消を維持する。クラウドの認識中だけ「クラウド認識中」とし、アップロードとサーバー認識を偽の進捗率で分けない。停止は無効、× は有効。録音は停止まで送信しない。

失敗時はピル / トレイに「文字起こしできませんでした（時間切れ）」等を控えめに表示し、成功・原文入力済みとは知らせない。表示は最長 3 秒、原因と設定導線はトレイにも示す。キー、応答本文、例外の生メッセージを使わない。色だけで区別せず支援技術名を付ける。

設定のローカル「実際の実行方式」は最後のローカル結果のまま保持し、クラウド使用によって CPU / Vulkan / CUDA 欄へ `cloud` を出さない。別途「今回の認識: クラウド」を表示する。実 GPU 名や Azure のデプロイをアプリが確認できたとは扱わない。

## 4. config.json と接続設定

### 4.1 schema 1 の追加契約

既存 `recognition.model` / `language` はローカル用として保持し、名称変更・入れ子への移動をしない。追加キーの欠損はローカル・空のクラウド設定で補う。次はクラウドを選択した場合の recognition 部分の例であり、既存の他の項目は同じ設定に残る。

```json
{
  "schema_version": 1,
  "recognition": {
    "model": "small",
    "language": "ja",
    "engine": "cloud",
    "cloud": {
      "base_url": "https://transcription.example.com/v1",
      "api_key_dpapi": null,
      "model": "whisper"
    }
  }
}
```

`null` は秘密未設定の説明用である。この外部送信先の例ではキー再入力まで録音は始めない。`whisper` は利用者の LiteLLM 側の名前の例で、クラウドの既定モデルにはしない。

| JSON パス | 型・許容値 | 既定値 / 検証 / 保存 |
| --- | --- | --- |
| `recognition.engine` | string enum `local` / `cloud` | 欠損は `local`。local のとき書き出さない。未知値・null はエラー、黙って local へ戻さない |
| `recognition.cloud` | object | 欠損は下記の既定値。全子項目が既定なら object ごと書き出さない。null はエラー |
| `recognition.cloud.base_url` | string | `""`。非空なら §4.2 の URL 検証。cloud 選択時に非空必須。空の既定値は書かない |
| `recognition.cloud.api_key_dpapi` | Base64 string または null | `null`。空キーは null に統一、null は書かない。非空は DPAPI 暗号文。復号不能でも勝手に消さない |
| `recognition.cloud.model` | string | `""`。cloud 選択時は空白だけを拒否。制御文字拒否。非空の利用者入力を大小文字変換・接頭辞追加せずそのまま送る。空の既定値は書かない |

既存 `recognition.model` の4値検証、`language=ja` の規則は維持する。非選択時でも追加キーの型・enum・非空 URL の構文・暗号文形式は検証するが、URL / モデルの必須条件は cloud 選択時だけ適用する。外部宛キーの欠損・復号不能は準備不能として通知し、ネットワークを呼ばない。正確な loopback 宛は認証不要サーバー用に空キーを許す。設定にある非空キーが復号不能なら loopback でも認証なしへ黙って切り替えない。

未知キー・重複キー・型違い・未来 schema・壊れた JSON の非破壊拒否、原子的保存、既存暗号文の維持は前任設計 §8 と同じ。新規既定設定と旧設定の通常保存では追加キーが一つも出ないことをフィクスチャで固定する。クラウド設定を残して local へ切り替えた場合は `engine` だけ省略し、設定済み cloud は維持する。明示的な「クラウド接続設定を消去」で三値を既定へ戻した場合のみ object も省略する。

schema 1 のままでも、**新しいキーを含むファイルを旧 exe が読める保証はない**。旧版の未知キー拒否により起動は設定エラーとなる。新版が旧設定を読む互換性と区別する。旧版へ戻すときは新版で local を選びクラウド設定を明示消去するか、導入前に利用者が確保した設定へ戻す。旧版は cloud 設定を無視して送信・上書きしない。更新の試験起動中に設定を書き換えず、クラウド設定保存後のダウングレード制約を説明する。schema を上げないことを完全な後方互換と記載しない。

### 4.2 URL・認証・モデル

ベース URL は既存の互換整文と同じ **API root を含む値**に統一する。LiteLLM が `https://transcription.example.com` で提供する場合、入力は `https://transcription.example.com/v1`。`TrimEnd('/') + "/audio/transcriptions"` で連結する。`/v1` を自動追加・除去せず、モデル API や Azure デプロイ URL への変換もしない。

| 入力例 | 要求先 |
| --- | --- |
| `https://transcription.example.com/v1` | `https://transcription.example.com/v1/audio/transcriptions` |
| `https://transcription.example.com/gateway/v1/` | `https://transcription.example.com/gateway/v1/audio/transcriptions` |
| `http://localhost:4000/v1` | `http://localhost:4000/v1/audio/transcriptions` |

既存 `CompatibleEndpointUrl.Validate` を共用し、HTTPS 必須、HTTP は正確な `localhost` / `127.0.0.1` / `::1` だけ、userinfo（空の `@` も含む）・空白・制御文字・query・fragment を拒否する。曖昧な URL 補正はせず、入力欄に `/v1` 込みの例と実際の要求先を表示する。リダイレクトは追わない。

API キーは `ISecretProtector` / CurrentUser DPAPI で独立の暗号文にする。平文を config、コマンドライン、ログへ入れない。秘密は伏せ字欄が未変更なら保存済み暗号文を維持し、消去は明示操作にする。復号後のキーに CR / LF 等の制御文字があれば準備不能とし、HTTP ヘッダーへ渡さない。別 PC / 別 Windows ユーザーでは再入力を要し、復号失敗でクラウドを使えなくても、本人が local を選び直せば既存のローカル認識を使える。

モデルは LiteLLM の `model_name` をそのまま渡す。`whisper` を `whisper-1` や `azure/...` へ置き換えず、一覧取得・存在確認・自動選択を追加しない。接続先がその名前を認めるかは実際の要求で決まる。

### 4.3 整文接続との共有比較

| 案 | 同じ LiteLLM を両段で使う場合 | 判断 |
| --- | --- | --- |
| 共通の URL / キーを常時参照 | 入力は一度だが、整文先変更が音声の送信先まで変更する。認識と整文で権限も異なり得る | 採らない |
| 完全独立、入力補助なし | 送信先は独立するが同じ設定の再入力が必要 | 動作は単純だが入力負担が残る |
| **独立保存＋明示コピー** | 「整文の互換接続からコピー」で URL / キーだけを一回複写し、以後は連動しない | **推奨** |

コピー元は `cleanup.compatible` の保存済み値に限定し、現在の整文選択が OFF / ChatGPT でも、互換設定が有効なら利用できる。整文モデルはコピーせず、クラウドモデルを別途入力する。キー暗号文は同じ DPAPI 保護契約の下で複写でき、元が復号不能ならコピーを成立させず再入力へ案内する。既存の入力を上書きする操作は UI に明示する。コピーだけではエンジンを cloud へ切り替えず、保存前に送信先を確認できる。保存後に整文設定を変更・消去しても認識設定は変わらない。

## 5. 失敗時の意味論と推奨

### 5.1 選択肢比較

| 案 | 救済できる範囲 / 問題 | 推奨判断 |
| --- | --- | --- |
| セッション失敗として通知し終了 | 原文のない失敗を明確にする。待ち時間と挙動が予測可能。ただし発話のやり直しが必要 | **初回追加の推奨** |
| ローカルへ自動フォールバック | 同じ PCM を救済できる場合があるが、モデル未取得・破損、ロード時間、認識品質の変化、追加資源を扱う必要がある | 初回追加では採らない |
| HTTP 自動リトライ | 一時障害には効くが、送信完了後の応答喪失は処理・課金済みか判別できず、待ち時間も延びる | 自動リトライ 0 回。429 の Retry-After で待ち続けない |
| RAM に音声一件を残して手動再認識 | 再録音を減らせるが、保持状態・退出・設定変更・再送の UI が増える | 本追加の範囲外 |

ローカル自動復帰を採らないので、クラウド選択時は **ローカルモデル未取得でも録音可能**とし、起動時のモデル取得案内も出さない。ネットワーク失敗後にモデルを取得したり別のモデルへ勝手に変えたりしない。本人がローカルへ切り替えたときは従来どおりモデル準備を要する。

将来 D-7 で自動復帰を選ぶなら、別途「検証済みの選択モデルがある場合だけ一回」「未取得 / 破損なら取得せず認識失敗」「利用者取消では復帰しない」「クラウドとローカルを同時投入しない」「復帰中表示と追加待ち時間」を決定する必要がある。本書のタスク列は推奨の非復帰案を前提にし、未決のまま隠れた復帰を実装しない。

### 5.2 分類と通知

| 条件 | 挙動 / 通知例 |
| --- | --- |
| 認証 401 / 403 | 失敗、非投入。「文字起こしできませんでした（認証エラー）。設定を確認してください」 |
| 404 / モデル不明、429、5xx、その他非 2xx | 失敗、非投入。安全な HTTP 番号と固定分類だけを示す。生のサーバー本文を表示しない |
| 413 | 失敗、非投入。「音声が接続先の上限を超えています」。圧縮・分割・ローカル再送を自動実行しない |
| DNS / TLS / proxy / 接続断 | 失敗、非投入。「文字起こしできませんでした（接続エラー）」、直結への逃避なし |
| 全体 60 秒 | 失敗、非投入。「文字起こしできませんでした（時間切れ）」 |
| 不正 JSON、text 欠損 / null / 非文字列、応答上限超過 | 失敗、非投入。「文字起こしの応答を解釈できませんでした」等の固定分類 |
| `text` が空 / 空白だけ | 非投入。「音声を認識できませんでした」。無音だったと断定せず、再送なし |
| 利用者取消 | 通知で失敗と扱わず、非投入。整文もローカルも始めない |

「発話を失わない」は前任設計 §3.3 と同じく、**認識に成功して原文が存在する後段での保証**である。クラウド認識に失敗すると原文自体がなく、整文のような原文フォールバックはできない。終端失敗では PCM を解放し、やり直しを要することを明記する。音声・履歴の永続保存、OS 終了を超える復元保証は追加しない。これで本人の要求を満たすかは D-7 として判断を残す。

## 6. 音声形式・ファイル上限

### 6.1 メモリ上の WAV

WASAPI の入力そのものが 16 kHz WAV であるとは仮定しない。現行録音はデバイス形式の mono float を保持し、`StopAsync` の最後に 16 kHz float 配列へ変換する。クラウド側はその **認識直前の PcmAudio** から次のファイルを作る。

| 項目 | 決定 |
| --- | --- |
| コンテナー / 符号化 | RIFF/WAVE、PCM format tag 1、little endian、16 bit signed |
| レート / チャネル | 16,000 Hz / mono。byte rate 32,000、block align 2 |
| float 変換 | 有限値を [-1, 1] に clamp し、負側 32768・正側 32767 の倍率で丸め PCM16 へ飽和変換。NaN / Infinity は入力異常として送信前失敗 |
| ヘッダー | 追加チャンクなしの 44 byte。data 長は `Samples.Length × 2`、RIFF 長はファイル長 − 8 |
| multipart の file | 固定ファイル名 `speech.wav`、Content-Type `audio/wav`。日時・ユーザー名・元ファイルパスを含めない |
| 保存 / 依存 | メモリ内だけ。録音用一時ファイル、FFmpeg、圧縮 codec の同梱を追加しない |

ローカル認識へ渡す float 配列は変えず、WAV 化はクラウドのアダプター内だけで行う。PCM16 の量子化と WAV コンテナー化だけが追加変換であり、再リサンプルしない。上限判定を確保・エンコード前に checked な 64 bit 計算で行う。

### 6.2 上限に当たる録音長

OpenAI の公式ガイドは入力上限 25 MB と WAV 対応を示している。互換サーバーが同じ上限を持つ保証はない。[OpenAI File transcription](https://developers.openai.com/api/docs/guides/speech-to-text)（2026-11-18 確認）

本アプリでは **WAV ファイル全体 25,000,000 byte 以下**をクラウド送信の内部上限とする。25 MiB と解釈して大きくしない。`44 + 2N <= 25,000,000` より最大 N は 12,499,978 サンプル、781.248625 秒（約 13 分 1 秒）。10 秒は 320,044 byte、30 秒は 960,044 byte となる。multipart の境界・モデル名等はこのファイル上限に含まれないが、サーバーの要求全体上限には含まれ得る。

録音停止・末尾回収後の実サンプル数で厳密に判定し、超過なら **送信 0 件で認識失敗**にする。先頭だけ送る、末尾を削る、チャンク分割、圧縮、ローカルへの自動復帰はしない。接続先がより小さい上限を持つ場合は 413 等として終了する。自動で上限値を問い合わせない。

クラウド選択欄に「短い発話向け。WAV 上限 25 MB（約 13 分）。超過時は文字起こしできません」と表示する。既存の録音操作・ローカル録音の長さを変更せず、今回の推奨は録音中の自動打切りを追加しない。超過後に復元できない制約と、現行の長時間録音メモリ課題（前任 U-03）は D-8 に示す。録音長の安全上限や分割が必要なら別仕様とする。短時間用途のため、上限付近まで必ず 60 秒以内に認識できるとは保証しない。

## 7. HTTP 契約と期限

### 7.1 要求と応答

`CloudTranscriber` は `HttpClient` / `MultipartFormDataContent` / `System.Text.Json` を使い、`POST <base_url>/audio/transcriptions` を送る。multipart の boundary はライブラリに生成させる。フィールドは **file / model の2つだけ**を初回の共通契約とする。非空のキーは `Authorization: Bearer <key>` にだけ入れる。空キーを許す loopback では Authorization を付けない。

`language`、`response_format`、`temperature`、`prompt`、`stream`、時刻情報・話者分離・翻訳指定は追加しない。ローカル認識の `ja` 固定を変更する提案ではなく、クラウドは対応差の小さい最小契約で日本語音声の文字起こしを求める。日本語の品質と、追加指定なしで JSON を返す互換性は実地確認の受け入れ条件とする。モデル固有パラメーターが必要な接続先を黙って追加対応しない。

成功は 2xx、完全に受信した JSON object のトップレベル `text` が文字列で、Trim 後に非空の場合だけとする。追加フィールドは無視し、`choices`・SSE・平文・部分 JSON・部分認識結果を代替入力にしない。空文字列は無音相当の非投入、欠損 / null / 非文字列は不正応答として区別する。Chat Completions の `finish_reason` は文字起こしには要求しない。

応答の上限は UTF-8 **1 MiB**。Content-Length が超過なら本文を読まず終了し、未指定・虚偽の長さでもストリームの実バイト数で制限する。エラー応答も本文をログ・通知へ出さず、失敗分類・HTTP 番号だけを返す。音声、認識結果、秘密、URL query、リクエスト / レスポンス本文、例外全文のファイル出力を追加しない。

### 7.2 60 秒の全体期限

クラウド認識は **60 秒固定**とし、設定キーや調整 UI を追加しない。PCM 確定後に認識を開始した時点から、上限検査、WAV 化、接続・TLS・proxy 認証、アップロード、サーバー待ち、応答本文の受信・解析までを含む。録音時間と既存の停止末尾回収は含めない。

短い 10 / 30 秒発話を主対象に、整文より大きい要求と認識待ちの余裕を取る設計値であり、実測値ではない。認識成功後に整文を選んでいれば、従来どおり別の 15 秒が始まる。停止→投入の上限を 15 秒や 60 秒と誤表示せず、認識＋整文は最大概ね 75 秒に停止処理・投入時間が加わる。

クライアントは `CreateClient(Transcription, timeout: InfiniteTimeSpan)` と共通 deadline token を使い、ヘッダー後に本文が止まった場合も同じ期限で止める。エンコードのループでも token を確認する。NetworkContext の既定期限も Transcription は 60 秒にし、明示期限なしの呼出しが無限にならないようにする。既存の接続期限 30 秒はそのまま全体期限の内側で働く。Coordinator の保険も同じ開始時点・残り時間を使い、二重に 60 秒待たない。

## 8. NetworkContext の拡張

**NetworkPurpose.Transcription を追加する。** Cleanup の名前のまま音声を送ると、通信種別・試験・送信データの境界が曖昧になる。入口を増やすのではなく、前任設計 §9 の共通入口 `NetworkContext.CreateClient` の用途 enum を4種へ拡張する。

| Purpose | 対象 / 規則 | 失敗時 |
| --- | --- | --- |
| Transcription（追加） | 音声 multipart POST。HTTPS / 正確な loopback HTTP、転送なし、60 秒 | 原文なし、非投入で終了 |
| Cleanup（既存） | 互換整文 / ChatGPT の認証・整文等、既存の policy、15 秒 | 原文投入 |
| Update / ModelDownload（既存） | GET/HEAD の検証済み HTTPS 転送 | 既存どおり |

現行コードの `purpose != Cleanup` をそのまま拡張すると Transcription に GitHub の転送 policy が割り当たる。これを避け、**転送許可は Update / ModelDownload の明示列挙**とする。呼出し側が RedirectPolicy を渡しても Transcription は転送しない。`CheckScheme` の HTTP 許可対象も用途ごとに明示する。Transcription は URL validator と同じ正確な3形だけを許可し、広い `RoutingProxy.IsLoopback` 判定を HTTP の許可条件に流用しない。既存 Cleanup の HTTP 許可と、共通の proxy bypass の振舞いは変更しない。

環境変数 / 手動 / なし、NO_PROXY、loopback の直結、手動の資格情報 / Windows 統合認証、環境変数の既定資格情報、TLS 信頼ストアは既存 NetworkContext に委ねる。不正 proxy や 407 で黙って直結しない。Bearer は API 宛、proxy 資格情報は proxy 宛であり、相互に流用しない。HTTP stack の認証 handshake と、アプリによる自動 POST 再試行を区別する。

アプリ起動、設定を開くだけ、local 選択中、録音中にはクラウド API を呼ばない。認識に必要な一要求のみとし、事前接続・モデル一覧・自動 probe は行わない。更新・モデル取得や既存 ChatGPT の必要な付随通信まで禁止する意味にはしない。

| 成功後の整文 500 / 停止 / 15 秒 | 文字起こしの原文を一度だけ投入。認識 60 秒とは別計測 |
| 認識 HTTP・JSON・空・上限・接続失敗 | §10.1 の固定分類、非投入、整文要求 0、Idle。空 text はエラー分類と区別 |
| 応答なし・本文途中停止 | 実 60 秒で認識終了（試験許容は 60 秒＋後始末 2 秒）。原文復帰はない。遅延完了による追加投入 0 |
| 録音 / upload / 認識待ち中の取消 | 投入・整文・ローカル認識 0。転送・再試行なし。次セッション成功 |
| local 選択 / 未設定 / DPAPI 復号失敗 / サイズ超過 | クラウド要求 0。local 以外の失敗はローカル認識へ回らない |
| redirect / echo エラー | 転送先 0 件。ダミーキー・音声・本文が標準出力へ漏れない |

HTTPS / proxy の経路証拠には既存 `Fixtures/NetFixtures.cs` 等の TLS fixture と記録用 CONNECT proxy を拡張する。loopback HTTP の成功だけを外部 HTTPS や統合認証の証拠にしない。

### 10.3 診断 probe（予定インターフェース）

M3 同様に実 exe の非対話診断を設ける。以下は **未実装の予定コマンド**であり、この設計作成では実行しない。

```powershell
whisparrot.exe --write-transcription-config <test-config.json> --url <api-root> --model <name> --key-env <NAME>
whisparrot.exe --transcription-probe --config <test-config.json> --wav <fixture.wav>
whisparrot.exe --pipeline-file <fixture.wav> --use-settings --config <test-config.json>
```

設定作成は既存設定を読んで recognition 部分だけを更新し、未知・未来 schema を上書きしない。キーは環境変数名で受け、値を表示しない。probe は cloud が選択されている設定を要求し、同じ準備・認識経路を通す。外部音声送信は利用者がこのコマンドを実行した場合だけで、自動起動・設定保存で実行しない。

出力は状態、elapsed_ms、recognition_outcome、failure_kind、HTTP status、injected_count、文字数だけを既定とする。本文はテスト fixture 用の明示 `--show-text` を指定した場合だけコンソールへ出し、実地確認ではシェルの出力保存を行わない。実際の前景アプリへ貼り付けず、録音・投入の OS 動作と区別する。認識成功（空 text を含む）は終了コード 0、認識・設定失敗は非ゼロとし、E2E は注入件数と分類を別に検査する。外部タイムアウトは 60 秒より十分長くし、整文付き pipeline は 75 秒＋準備・投入の余裕を取る。

### 10.4 利用者による LiteLLM＋Azure の実地確認

1. 利用者が LiteLLM 側で文字起こしモデルの公開名（例 `whisper`）と Azure のバックエンド設定を用意する。サービス・モデルの有効性、キー権限、ログ / 保存方針を接続先側で確認する。Azure 固有設定は LiteLLM にだけ置く。
2. Windows の専用テスト設定でクラウドを選び、API root（`/v1` 込み）、LiteLLM キー、公開モデル名を保存する。ローカルモデルを置いていない状態でも準備できること、音声送信説明と宛先を確認する。まず整文 OFF で試す。
3. 許諾済みの 10 秒 / 30 秒の日本語 WAV を probe で送り、成功、数字・否定・固有名詞、末尾、経過時間、実 WAV 形式を確認する。結果本文を公開ログや報告書に載せない。LiteLLM 側で要求先・モデル経路が期待どおりであることを安全なメタデータで照合する。
4. 対話デスクトップでホットキー→実マイク録音→停止→メモ帳への投入を確認する。ピル・フォーカス・クリップボード復元・取消を確認する。非対話 probe の成功を実マイク / ピル / 貼付けの合格にしない。
5. 整文を互換にし、必要なら「整文の互換接続からコピー」を用いて同じ LiteLLM を使う。音声認識モデルと整文モデルを別々に設定し、両方成功、整文先停止でクラウド認識原文の一回投入、ChatGPT 選択時の既存経路も確認する。
6. 専用の誤キー・不明モデル、接続先停止、認識中取消で非投入を確認する。60 秒停止・413・巨大応答等の故障注入は原則モック側で行い、実サービスへ不要な大容量要求を出さない。
7. 必要な proxy モード、HTTPS / TLS、NO_PROXY、統合認証を実経路で確認し、local へ戻すと音声要求が出ないことを確認する。クラウド設定のコピー元を変更しても音声宛先が変わらないことも確認する。
8. Windows build / arch、本体・LiteLLM の版、公開モデル名、接続の構成、10 / 30 秒の時間・成否、未確認項目を記録する。秘密、個人依存のホスト名、音声、発話本文は公開報告に含めない。実地結果が得られるまで LiteLLM＋Azure を検証済みと記載しない。

### 12.2 実装で隠さない境界

| リスク | 対応と判断条件 |
