#### native の展開方式（判断理由）

**設計 §2.2 の自前展開を採用した**（`IncludeAllContentForSelfExtract` は使わない）。

- 実装: ビルド時に Whisper.net の native（`runtimes/win-<arch>/` と、`-Backend vulkan` のときの `runtimes/vulkan/win-x64/`）と VC++ 再頒布 DLL を `EmbeddedResource` として exe に埋め込み、NuGet の targets が出力へ入れる native（全 OS・全アーキ分）はすべて外す（スパイク S-03 の Prune に相当）。実行時は `NativeRuntime` が `%LOCALAPPDATA%\whisparrot\runtime\<version>\<arch>\` へ、**要求バックエンドに必要な分だけ** SHA-256 確認付きで原子的に配置する（一時ファイル → `File.Move(overwrite)`、同時展開・使用中でも内容が一致すれば成功扱い）。
- 実測した利点: 展開されるのは約 2〜60 MB の native のみ（ARM64 CPU: native 4 + VC++ 4 の計 8 ファイル）で、スパイクの `IncludeAllContent` の「約 460 ファイル / 157〜170 MiB を `%TEMP%` へ」より大幅に小さい。`AppContext.BaseDirectory` が展開先を指す副作用もなく、設定・モデルの基点を exe のフォルダに保てる。2 回目以降は全ファイルをハッシュ確認のうえ再利用（ARM64 で 25 ms）。改ざん・破損は起動時に修復される（Vulkan DLL を破壊して起動 → 元の 58,013,696 bytes に復元されることを確認）。
- 難しかった点: Whisper.net の `RuntimeOptions.LibraryPath` は「ライブラリのファイルパス」ではなく、**その親ディレクトリを `runtimes/<backend>/<rid>/` の検索ルートとして使う**（デコンパイルで確認）。展開ルートに `runtimes/` を同じ階層で作り、`LibraryPath` に展開ルート直下の仮のファイル名を渡すことで解決した。ライブラリのロードは Whisper.net が依存順に絶対パスで行う。
- .NET / WPF 自身の native は引き続き `IncludeNativeLibrariesForSelfExtract` でホストが展開する（publish 出力は `whisparrot.exe` 1 ファイルのみ。pdb を除く）。
- VC++ ランタイム: 展開後、`vcruntime140` → `vcruntime140_1` → `msvcp140` → `vcomp140` の順に絶対パスで先読みし、後続の `whisper.dll` などの依存解決をアプリローカル版へ向ける。**この VM にはシステムの VC++ 再頒布パッケージが入っているため、同梱 DLL だけで起動できること（素の Windows）は未検証**。同梱した DLL は Visual Studio Build Tools の再頒布フォルダ（14.44）のもの。

## 2. ビルド手順と publish 結果

### ビルド・テスト（Windows、.NET SDK 10）

```powershell
dotnet test tests\Whisparrot.Tests -c Release        # 49 件。Core の状態機械・プロトコル・展開・音声変換・認識の親側
build\publish.ps1 -Arch all                          # arm64 | x64 | all。出力: out\win-<arch>\whisparrot.exe
build\publish.ps1 -Arch x64 -Backend vulkan          # x64 のみ Vulkan を追加で埋め込む（実 GPU 検証は T10）
```

- `build\publish.ps1` は `vswhere` などで VC++ 再頒布 DLL の置き場（`VC\Redist\MSVC\<ver>`）を探し、`-p:VcRedistDir=` として渡す。見つからなければ警告を出し、VC++ ランタイムは同梱されない。
- publish は `SelfContained` / `PublishSingleFile` / `EnableCompressionInSingleFile`（既定）。`PublishTrimmed=false`。
- モデルは `whisparrot.exe` と同じフォルダの `models\ggml-small.bin` に手動配置する（コミット対象外。`.gitignore` で `*.bin` / `*.wav` / `out\` を除外）。
- 診断モード（`whisparrot.exe` の引数）: `--native-info`、`--pipeline-file <wav> [--model p] [--repeat N] [--cancel-after-ms N] [--backend cpu|auto]`、`--record-probe [ms] [--cancel]`、`--clipboard-probe`、`--pill-probe`。GUI サブシステムの exe なので、PowerShell では `& exe ... 2>&1 | Out-String` のようにパイプして実行する（`cmd` の直接実行では出力を受け取れない）。

### exe サイズ（実測、モデル除く、圧縮込み）

| 構成 | バイト | MiB |
| --- | --- | --- |
| win-arm64 / CPU | 73,843,301 | **70.4** |
| win-x64 / CPU | 77,789,450 | **74.2** |

### 起動・認識の実測（ARM64 VM、2 vCPU、スレッド 1、small、非対話）

- 待機: トレイ起動 5 秒後の working set は約 229 MiB（スパイクのピル placeholder の約 82 MiB より大きい。WPF + WinForms + 実体のピル + Coordinator。原因の切り分けはしていない）。
- 認識: 約 5 秒の音声で `Recording → Idle` の合計 約 14.2 秒（ARM64、モデルロード込み）、同じ子を再利用した 2 回目は約 12.7 秒。x64（エミュレーション）は約 25〜27 秒。**この VM の速度は設計の合格目安（Iris Xe の x64 実機）とは比較できない**。

## 3. 日本語認識の確認

- 方法: macOS の `say -v Kyoko` で日本語の文を合成し、`afconvert` で 16 kHz / mono / PCM16 の WAV にした（音声ファイルは commit していない）。Windows の `whisparrot.exe --pipeline-file` で、**本物の Coordinator と子プロセスの認識ワーカー**（lang=ja、small）に通した。
- 結果（想定キーワードは「天気」「会議」「午後」「ホットキー」「日本語」）:

| 入力音声（合成） | 認識結果 | 構成 |
| --- | --- | --- |
| 「今日はいい天気ですね。明日の会議は午後三時から始まります。」 | 「今日は、いい天気ですね。明日の会議は、午後3時から始まります。」 | ARM64 ネイティブ CPU、x64 エミュレーション CPU、いずれも同一 |
| 「ホットキーを押して、日本語で話すと、文字が入力されます。」 | 「ホットキーを押して日本語で話すと文字が入力されます」 | x64 + Vulkan 同梱ビルド（GPU 無しのため CPU 実行） |

- 想定キーワードはすべて含まれた。**合成音声の読み上げでの確認であり、実際の人の声・雑音・フィラー等での精度は評価していない**（D-3 の範囲）。

## 4. 設計からの逸脱

| 点 | 内容と理由 |
| --- | --- |
| native 展開 | 設計 §2.2 の自前展開を採用（逸脱ではなく設計どおり）。ただしパスは `runtime\<version>\<arch>\` 直下に `runtimes\<backend>\<rid>\` を置く構造（Whisper.net の検索規則に合わせたため）。設計 §2.2 の `<backend>` 階層との差は、要求バックエンドに必要な分だけ展開することで同等の分離を保つ |
| 子プロセス | 設計は「親子の中断が効かない処理は子を終了」。実装も同じ。ワーカーは認識後も生存してモデルを保持し（設計 §3.2）、取消・失敗時に終了する。待機中のモデル常駐で working set が増える（small で約 0.8 GB）。待機中に常駐させない運用が要るかは未決 |
| タスク範囲 | 設計の `tests/Whisparrot.Integration/` は作らず、結合に相当する確認は診断モード（`--pipeline-file` など）と手動実行で代替した。自動化は T17 |
| 診断モード | 設計に無い診断用の引数を `whisparrot.exe` に追加した。非対話環境で本物の経路を通すための手段。製品機能ではなく、T17 で扱いを見直す |
| ホットキー全滅時 | 設計 §5 は「本人と決める」。M1 は通知だけ行い、トレイからの開始/停止で継続する。設定導線は T14 |
| 未投入一件の再試行・破棄 | 設計 U-07 の最小解釈（トレイに一時表示）を T06 で先行実装した（状態機械とトレイ項目まで） |

3. **クリップボード復元**: 事前に別の文字列（可能なら HTML / 画像 / ファイルも別々に）をコピーしてから 2 を行い、投入後に元の内容が戻ること。投入中に別アプリでコピーした場合は、そちらが残ること。
4. **取消**: 録音中・認識中にピルの × で取消 → 何も入らず、タスクマネージャーに `whisparrot.exe`（子）が残らず、マイク使用中表示が消えること。
5. **ピル**: 画面下中央に表示される、停止・取消をクリックしてもメモ帳のキャレットが失われない、100 / 150 / 200% DPI で作業領域内に収まる。

7. **マイク**: 実際の発話で語尾が欠けないこと（末尾 250 ms の回収）、既定デバイスの切り替え・切断時の挙動。
